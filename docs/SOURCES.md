## 座標の同定と検証（自動層）

1. OSM 駅ノード照合（種別と運営事業者でランク付け）→ 16,582 駅。
2. 表記差（ヶ⇄ケ・挾⇄挟 等）で一致しなかった 129 駅は、日本語版ウィキペディア記事→Wikidata P625、または記事自身の座標で後補し、`位置.坐标来源` に出典を残しました。
3. 線内分布テスト（同一线路の他駅中央値＋98パーセンタイル×1.5）で 240 駅が**別県の同名駅**と一致していたことを検出し、線内の正しいノードへ差替えました（`位置.坐标修正` に旧値・偏差・根拠）。
4. 差替え根拠が無い 42 駅は座標を変更せず `データ品質.座標 = 線外疑い` で標記しています。
5. 座標が取得できなかった 4 駅（廃止ケーブルカーの停留場で記事・OSM・Wikidata すべてに個別座標無し）は `データ品質.未得理由` に理由を記載しています。

### 失敗した検証の記録（透明性のため残す）

当初 `名称.词条` から導したウィキペディア座標を正として 86 駅を一括置換しましたが、`词条` は eki-wiki が同じ駅名の記事に解決した**派生リンク**にすぎず、鹿児島市電の中郡駅が JR 米坂線（山形県）の記事に化けているような例がありました。置換は誤りだったため 77 駅は旧座標へ復元し、線内分布テストを通過した 9 駅のみ修正を維持しています。各駅の結果は `位置.坐标修正.判定`（旧座標のみ線内／新座標のみ線内／両者線内＝要人手）に保存しました。

## 官网リンクの検証

- 自動層：抽出した官网 115,055 件を HTTP ステータスで到達確認。応答なし・4xx/5xx は `官网` を `null` にし、`官网_欠陥` に理由を保存（21,675 件）。検証済み 89,905 件は `官网検証.HTTP` に code と日付。同ドメインの打査上限により未検証 25,150 件は、削除せず**未検証のまま**保持しています。
- 加精層：`人手確認: true` の記録は **実際に本文を読むまで開いたページのみ** を `出典` に記載。到達できなかった公式（鶴岡八幡宮・久岐神社・鎌倉国宝館・名古屋城 等）と 403 を返すサイト（JR東日本・東京メトロ）は出典にしていません。

## 再現実行

```
python3 scripts/build_osm_index.py        # japan-latest.osm.pbf → jp_poi.sqlite3（駅・POI・面の重心）
python3 scripts/run_lines.py              # 577 路線 → data/lines/*.json
python3 scripts/enrich2.py                # 官网・Wikidata・三語名称の補強とHTTP検証
python3 scripts/zh_fixup.py               # converttitles=1 で中文ウィキ見出しを解決
python3 scripts/coord_pool_fix.py         # 表記差駅の座標後補＋POIプール再生成
python3 scripts/coord_outlier.py --apply  # 線内分布テスト（同名異県駅の差替え）
python3 scripts/coord_flag.py             # 差替え根拠の無い駅を警告のみ付与
python3 scripts/curate_gen.py --per-cluster 8
python3 scripts/make_docs.py              # docs/ と index.json の再生成
```
